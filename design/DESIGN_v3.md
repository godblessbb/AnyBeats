## 1. 数据模型（写进下一单的 `src/core`）

格子只是视图，数据里记的是 **tick**。

```ts
const TICKS_PER_BEAT = 48;          // 1/8 = 24，1/16 = 12，1/32 = 6，八分三连 = 16，十六分三连 = 8
const BEATS_PER_BAR = 4;            // 一格 = 一拍（一个四分音符），一小节 4 格

type SlotKind = 'word' | 'hold' | 'rest';   // 字位 / 拖音 / 空音

interface Slot {
  id: string;
  tick: number;        // 在这一行（这一小节）里的起点，0 – 191
  len: number;         // 占多少 tick，≥ 1
  kind: SlotKind;
  text: string;        // 只有 word 有；还没填字时是 ''
}

interface Line {       // 一行 = 一句，默认就是一小节
  id: string;
  bar: number;         // 从第几小节开始（全曲绝对小节号）
  slots: Slot[];       // 按 tick 升序，互不重叠；没铺的位置就是没有 slot（表格里是空格子）
}

interface Section { id: string; kind: 'intro' | 'verse' | 'hook' | 'bridge' | 'outro'; label: string; lines: Line[] }  // label 例：'Verse 1'

interface RhymeRule {  // 一种颜色 = 一条规则，整首通用
  id: string;
  hue: number;         // 色相，界面颜色都由它派生，避开 250–310°
  count: 1 | 2 | 3 | 4;           // 单押 … 四押
  finals: string[];    // 长度 = count，从前往后对应格内最后 count 个字位
}

interface Project {
  bpm: number; offsetMs: number; beat: BeatRef;
  sections: Section[];
  rules: RhymeRule[];
  paint: Record<CellKey, RuleId>;          // CellKey = `${lineId}:${beat}`，一格只能有一种颜色
  locks: { lines: LineId[]; beats: number[]; cells: CellKey[]; rhymeSlots: boolean };
}
// 撤销历史（History<Project>）和作品一起存进本机浏览器（见第 2 节「六」）
```

- 字在格子里按 `tick / 48 × 格宽` 摆。格底 4 条淡刻度线就是 0 / 12 / 24 / 36 tick。
- 三连：一拍里落点是 0 / 16 / 32 的三个字位，界面在这一格上方画一条细括线，标「3」。
- 1/32：一个 16 分位置拆成两个 6 tick 的字位，字号小一号。
- 一格里的「韵脚位置」不另外存，每次现算：这一格的字位按 tick 排好，取最后 `count` 个。拖音和空音不算（见拍板题 1）。
- 换 BPM 时 tick 不动，只有秒数跟着变。所以歌词「跟着拍子走，不跟秒数走」。

## 2. 逐项说明

### 一、歌词区 = 类 Excel 表格
- **一格 = 一拍**，一小节 4 格，一行一句（默认一句一小节）。列头是 1–4 拍，行头是小节号。格线、表头底色都按电子表格画：行头和第 1 拍之间是一条深色粗线（小节起点）。
- **格内的字按 tick 摆**，格底 4 条很淡的 16 分刻度线，不用下划线。第 4、8 小节第 1 拍是三连（标「3」）；第 5 小节第 2 拍的「在节」是两个 1/32。
- **列头每拍分 4 个小刻度**：点拍号选整拍那一列；点小刻度选这一拍里那个 16 分位置。`flow.html` 里选中的是第 2 拍第 3 个 16 分：小刻度变成朱橙色，整首这一列用两条朱橙竖线框出来（只画线，不铺底色，免得和涂色混）。
- **段落标签用英文**：Intro / Verse 1 / Hook（另有 Bridge / Outro）。表格段落头和轨道区标尺用同一套名字。
- 落在：所有画面。

### 二、先做 flow，再填字和韵脚
- 顶栏一个步骤切换：**① 铺 flow → ② 填字和韵脚**。两步随时能来回切。
- **空字格三种，一眼分清**（三种样式两两至少有两项可见特征不同，自检脚本实测）：
  - 字位：**实线圆角框**（白底）。之后在这里填一个字。写了字以后框变浅，字是正文色。
  - 拖音：**实心灰色横条**，紧贴在前一个字后面，表示前一个字拖长占这个位置。
  - 空音：**虚线框 + 浅灰底**，表示停顿。
- **一格里两个位置**的两种组合在右栏用小样例画出来，表格里用 ① ② 标出实例：① 一个字拖两个位置（第 3 小节第 1 拍「霓 ━ 虹 ━」）；② 一个字 + 一个空音（第 5 小节第 3 拍「光 ▢」）。
- 铺 flow 的手段：画笔（字位 / 拖音 / 空音）+ 落点精度（1/8、1/16、1/32、三连），点格子里的位置就铺；「复制到下一行」「清空这一行」。由 AI 铺（「AI 铺第 8–9 小节」）在右栏画成「接入后」。
- 第二步往字位里填字和韵脚：点字位直接打字，或在押韵面板的候选里点一下填进选中格的韵脚位置。
- **导唱**（`flow.html` 轨道区下面，标「后续实现 · 静态版先不做」）：入口是「生成导唱」按钮。导唱轨和伴奏波形用同一条时间轴，**每个字位「嗒」一声（一个灰块），拖音把这一声拉长（浅灰长块），空音不出声**，块数 = 字位数（示例 89 个，脚本实测相等）。
- 落在：`flow`；第二步在其它所有画面。

### 三、色块押韵
- **押韵面板最上面是一排彩色矩形**（蓝 / 绿 / 粉 / 金 + 虚线「+」新建）。手机上这排色块直接放在收起的抽屉把手里。
- 操作顺序：**先选颜色，再选格子**。工具条和面板里都有选法：单格 / 整行 / 整列 / 框选，加一个「反选」开关。`paint.html`：选金色 → 点第 7 小节行头整行选中（行头变朱橙底）→ 开「反选」点掉第 1、4 拍（这两格变成虚线框 + 「已去掉」）→ 剩下 2 格是朱橙实框 → 「涂上金色（2 格）」。
- **一格只能有一种颜色**：第 4 拍已经是粉色，面板里写明它为什么被去掉。表格里格子底色和韵脚字的底色都从同一个色相派生，脚本逐格量：一格里只出现一个色相。
- **一种颜色 = 一条韵脚规则，整首都成立**：选中颜色后定押数（单押 / 双押 / 三押 / 四押，分段按钮，最多四押），下面出现同样个数的韵母框（双押就是两个框：「i」「ang」）。
- **押韵永远落在格内最后的字上**：单押 = 最后一个字位，双押 = 最后两个字位……这几个字位底色加深一档（同色相）。
- **涂了色、还没写字**的韵脚位置直接显示该位要押的韵母占位（`paint.html` 的 Hook：「u」「ou」）。可以手动填，也可以点候选。
- **AI 一次性填入**：静态版不出按钮。`paint.html` 右栏画了接上 AI 后的样子（虚线框 + 「接入后 · 静态版藏起来」）：「AI 填入 8 个韵脚」只填空着的韵脚位置，不动已写的字，填进来的字先标「待确认」，每格旁边有「采用 / 换一个」。
- **已写了字但韵母对不上**：只提示，不自动改。`full.html` 第 5 小节「远」（uan ≠ i）：字外面一圈暖色虚线，行尾一个小标签「『远』uan ≠ i」，右栏一句话说明。手机上抽屉把手显示「1 处对不上」。
- 韵母比对忽略介音：iang 和 ang 算同韵，uan / ian 和 an 算同韵。这和第一期按十三辙分组的口径一致（拍板题 6）。
- 落在：`paint`、`full`、`lock`、`drawer`（以及其它画面里的涂色）。

### 四、锁定
- 四种锁：**整行、整列、选中的格子、全部韵脚位置**（`lock.html` 四种同时出现）。
- **一眼可见**：锁住的格子铺一层灰色斜纹；锁的范围用小锁标在对应位置：整行锁在行头（「03 🔒」），整列锁在列头（「1 🔒」），单独锁的格子在格子左上角有一个圆形小锁，锁住的韵脚字在字的右上角有一个方形小锁。
- 入口：工具条「锁定」按钮；桌面右栏顶部是锁定面板（四项，每项后面写范围和状态），手机在底部浮条里。锁定的字不能改字、不能挪落点，AI 也不许动。
- 落在：`lock`；`ai` / `ai_reject` 里的韵脚锁；`history` 里的整行锁。

### 五、AI 选区润色（接入后）
- 静态版没有入口。这两个画面顶部有一条横幅「接入后 · 这个画面只在接上 AI 之后出现，静态版没有入口」，右栏整个面板外面也套着「接入后」虚线框。
- 选区：框选第 3–4 小节，表格上一圈朱橙框，框角标「选区 · 第 3–4 小节」。
- 面板写清三件事：**全文 9 句都给 AI 当上下文，只改选区；选区里 5 个锁定的字（来 · 西方 · 一场）不许改**。
- **默认保持骨架**（开关默认开）：字数和每个字的落点都不变，只换字。另有「允许改 flow」开关（默认关）。
- `ai.html`：结果预览逐行列出原句（删除线）和新句（换掉的字朱橙底），下面是程序比对的三条：选区外没改动 / 锁定的 5 个字没动 / 字数和落点没变。按钮「用这一版 / 再来一版 / 放弃」。
- `ai_reject.html`，**被拒状态**：程序逐字比对，AI 动了选区外或锁定位置，就整份作废、不上屏。提示文案：
  > **这一版作废了，没有上屏**
  > 程序逐字比对 AI 的结果，发现它动了不该动的位置，整份结果不用，表格保持原样：
  > · 第 5 小节第 1 拍「每」→「这」：在选区外
  > · 第 3 小节第 4 拍「西」→「远」：锁定的字
  > 表格上打「!」的就是它想改的位置。

  按钮「再试一次 / 看 AI 原文」。表格内容和 `full.html` 逐字一致（脚本实测）。
- 手机：面板变成底部弹出的半屏面板；表格自动滚到选区，露在面板上面。被拒时，作废提示排在设置项前面。

### 六、其他
- **一条撤销 / 重做历史**：顶栏「撤销 ↶ · 重做 ↷ · 历史」一组按钮（手机三个图标）。填字、铺 flow、涂色、锁定、AI 改写、换伴奏全进这一条历史。`history.html` 展开历史面板：最上面是可重做的步骤（灰字、虚线图标，「下一步重做」），中间一条朱橙线「现在在这里」，下面是做过的步骤，每条带时间。撤销后能再前进；**历史跟作品一起存在本机浏览器，刷新页面后还在**；在中间做了新改动，上面灰色的步骤会被丢掉（拍板题 8）。撤销 / 重做按钮的提示文字写出这一步是什么（「撤销：锁定第 3 小节整行」「重做：换伴奏」）。
- **录音整块隐藏**：没有录音键、没有人声轨、没有音轨（脚本断言页面上没有「录音」两个字，也没有可见的录音元素）。
- **伴奏可替换**：桌面在伴奏轨左边「替换伴奏」，手机在波形下面一行「替换」。新伴奏 BPM 不同时弹窗二选一：
  - 「保留原 BPM（92）」：新伴奏变速到 92 播放（慢 8%），整首速度不变（标「推荐：已经录过 / 练熟的作品」）；
  - 「改用新 BPM（100）」：整首按 100 走，字跟着拍子一起变快，一首从 1:52 变成 1:43。
  - 说明框：「歌词记的是『第几小节、第几拍、第几个 tick』，**跟着拍子走，不跟秒数走**。不管选哪个，每个字都还在原来那一拍上，不会错位；变的只是播放快慢。」底部一句：新伴奏首拍已自动对齐第 1 小节，换伴奏也能撤回。右上角 × 是「取消，不换伴奏」。
- **手机押韵抽屉展开态**（`drawer.html`）：见第 0 节。

### 保留的已定项
朱橙强调色 `#C2410C`（深色 `#FB8A4C`）；唯一播放键（桌面在顶栏，手机在第二行）；静态版不出现 AI 页签和 Worker 文案（「接入后」的画面例外，都有明显的虚线框 + 黑底「接入后」标签）。不用紫色（涂色色相避开 250–310°，脚本扫所有可见元素的颜色）、不用全大写、不铺满卡片（右栏是平铺分隔线，不套卡片）。界面中文，BPM、tick 和英文段落名除外。

## 3. 和 v2 相比推翻了哪些

| v2 的做法 | v3 改成 | 为什么 |
|---|---|---|
| 一格 = 1/16 拍，一小节 16 格 | 一格 = 一拍，一小节 4 格；字按 tick 摆在格子里，每拍 48 tick | 你 11-16 定的。16 格太碎，看不出句子；1/16 网格表示不了三连和 1/32。tick 模型让格子只是视图：以后想按半拍看也不用改数据 |
| 中文段落名（前奏 / 主歌 / 副歌 / 桥段 / 尾奏），v2 拍板题 1 推荐中文 | 英文 Intro / Verse / Hook / Bridge / Outro | 你定的。说唱写词本来就说 Verse / Hook，英文段落名在表格里更短，也不会和歌词混在一起 |
| 轨道区有人声轨，录音键在轨道区，一遍一条音轨 | 录音整块隐藏，没有录音键和音轨 | 你定的。这一期先把写词（flow + 韵脚）做扎实；录音代码留着，界面不出 |
| 自动句内着色：按十三辙自动给句内同韵字上色、双押自动连块 | 用户自己选颜色、自己涂格子；一种颜色 = 一条整首通用的韵脚规则 | 你定的。自动着色是事后「看出来」押了什么；色块是事先「定下来」要押什么，先定规则再填字，顺序和「先 flow 后字」一致。自动着色还会把碰巧同韵的字也染上，满屏是颜色 |
| 双押块：外面画同色圆角框 + 「双押」小字 | 押数是规则的一部分（单押 – 四押），押在格内最后 n 个字，用同色加深底标出来 | 押几个字由规则定，不用再靠框去「认」；也去掉了一种自造符号 |
| 草稿视图：先像备忘录一样写整段，再一键「铺到拍子上」 | 先铺 flow（空字格），再往字位里填字 | 你定的。先有节奏骨架再填字，字数和落点从一开始就对得上，不用「铺完再拖字微调」 |
| 句尾不押的自动提示（虚线标签「和上句 ai 不押」+ 押本句 / 押上句） | 不再自动比较上下句；只在「写了字但对不上本格颜色规则」时提示 | 规则由颜色定了，「上一句押什么」不再是判断标准。要不要保留做辅助提示，列在拍板题 5 |
| 每拍 2px 粗线 + 第 2、4 拍隔拍浅底 | 一格就是一拍：格线 + 格底 4 条 16 分刻度线 | 格子本身已经是拍，不需要再分组。隔拍浅底会和涂色底色冲突 |
| 重音字加粗、空拍浅灰格 | 空拍变成「空音」字格（虚线框 + 浅灰底）；重音这一期不画 | 空音现在是 flow 的一部分，需要明确的样式。重音不在 11-16 的决定里，先不占视觉（残留风险里记了） |
| 押韵面板：① 当前句尾 → ② 筛选 → ③ 候选 → ④ 主题联想 | 色块 → 规则（押数 + 韵母串）→ 选格子 → 候选 | 面板的主角变成「规则」，候选只是填字的手段 |
| 手机抽屉只画了收起态（审查员指出的缺口） | 收起态直接带色块，另画展开态（`drawer.html`） | 补缺口；收起时也能换颜色，涂色不用每次拉开抽屉 |

## 5. 需要你拍板的题

1. **押数计不计拖音位置？**
   - A（视觉稿现在的做法，推荐）：**不计**。押数只数字位，拖音和空音跳过。「路口——」拖了一拍还是双押「路口」。
   - B：计。拖音也占一个押韵位，「口」拖两格就算押了两位。
2. **不同颜色能不能是同一个韵母？**
   - A（推荐）：**能，但给提示**。新建规则时如果和已有颜色的韵母串完全一样，提示「和蓝色一样，要不要直接用蓝色」。同一个韵可能想分成「Verse 的」和「Hook 的」两组管理。
   - B：不能。韵母串完全相同就自动合并成一种颜色。
3. **AI 一次填韵撞上已经写了的字怎么办？**
   - A（视觉稿现在的做法，推荐）：**跳过**。只填空着的韵脚位置，已写的字不动；如果已写的字韵母对不上，照样只提示。
   - B：已写但对不上的也给一个候选，标成「待确认」，用户点「采用」才替换。
   - C：全部覆盖（可撤销）。
4. **导唱用什么形式？**
   - A（视觉稿现在的做法，推荐）：**每个字位一声短促的「嗒」**，拖音拉长，空音不出声，音高固定。本机合成，不联网，能马上做。
   - B：带音高起伏的哼唱（按句尾韵脚上扬 / 下沉），听着更像旋律，但要做音色。
   - C：接 AI 生成带字的导唱人声（接入后才有）。
5. **v2 的「和上句不押」自动提示要不要保留？**
   - A（视觉稿现在的做法，推荐）：**不保留**。规则由颜色定，只提示「对不上本格颜色」。
   - B：保留成一个可以打开的辅助开关，默认关。
6. **韵母比对忽略介音吗？**（iang 算不算押 ang，uan / ian 算不算押 an）
   - A（推荐）：忽略介音，和第一期十三辙口径一致。
   - B：严格按韵母字面比对。
7. **一句超过一小节怎么办？** 现在一行 = 一句 = 一小节。
   - A（推荐）：超出的部分折到下一行，行头标「续」，列头对齐不变。
   - B：这一行变成 8 格（两小节），列头跟着变。
8. **撤销后又做了新改动，可重做的步骤怎么办？**
   - A（推荐）：丢掉（常见做法，一条线）。
   - B：保留成分支，历史面板里能切回去（更复杂）。
9. **换伴奏弹窗默认推荐哪个？** 视觉稿推荐「保留原 BPM」（已经练熟的作品不变速）。新作品可以改成推荐「改用新 BPM」。
