## 0. 一页结论

1. **写词页 = v3.2 的方格页 + 一支画笔**。默认「打字」：点方格就打字，键盘规则和 v3.2 一字不改。在侧栏点一种颜色 = **拿起这支画笔**，点 / 拖格子就上色；再点同一个颜色、按 Esc、或点模式提示上的「完成」= 放下。锁定、AI 也在侧栏，它们要的选区用第三种「选格子」工具（点行头 / 拍头自动拿起）。**同一次点击永远只有一种意思**：手里是什么工具，点格子就做什么。
2. **模式一眼看得出**：工具条最左一颗模式提示（打字 / 涂色：粉色 / 选格子）、涂色时整张表外框是这种颜色、指针变画笔、色块上画笔、手机抽屉头换成这种颜色、涂色时没有光标也不弹键盘。
3. **押韵页（现网第 2 步）的 21 项功能逐项有去处**（第 2.7 节）：12 项原样搬进侧栏 / 表格，6 项换成画笔的做法，**删 3 项**：双击改一拍的字（和方格打字重复）、「涂上 / 擦掉」按钮（画笔直接涂）、反选开关（Shift 点 / 橡皮代替）。
4. **歌词页**：一小节一行（v4 里 122 行正好对上你的 txt），韵脚字同色、句内 ≥ 半拍的停顿留窄空隙、跟着播放高亮当前行。一句跨两小节 / 一小节两句时，给一个**只影响展示和导出**的「调整分行」（并成一行 / 从这个字起另起一行），推荐做，放最后一段实现。
5. **十三辙**：辙表就是代码里已有的 `FINAL_TO_GROUP`（`src/core/rhyme/syllable.ts`，传统十三辙）；y / w 开头的字先还原成 iao / üan / uang 再查表，逐字核过。**in / ing 不同辙**（人辰 / 中东），推荐依据见 4.4。实测：你的 v1 严格判 19/58 格不押、十三辙 0；v4 的词如果每种颜色只建一条规则，严格判 **56/117** 格不押、十三辙 0。
6. **「严格韵母」保留成一档**，作品级设置。**旧作品打开时还是严格**，顶上一条横幅写清「改成十三辙会少几处不押、哪些颜色要合并」，点一下才改，一步可撤销——不会悄悄变色。新作品默认十三辙。
7. **存档**：`.anybeats` 版本号**不升**（还是 3），加两个可选字段 `rhymeMatch`（`'thirteen' | 'strict'`）和 `lyricLayout`（歌词页手动分行）。没有 `rhymeMatch` = 旧作品 = 严格 + 横幅。
8. AI 四道检查的第 ④ 道从「显式严格」改成「按这个作品存的判押韵档」，仍是屏幕和检查同一个函数、同一个档（第 6 节）。
9. 顺手发现并在稿子里修了一个**现网就有的层级 bug**：第 1 步的字和粘住的列头同是 `z-index: 4`，往上滚时字压在列头上（第 2.9 节）。
10. 拍板题 9 道（第 8 节），和既有稿的冲突 16 条（第 7 节），实现分 4 段（第 9 节）。

## 2. 合并后的「写词」页

### 2.1 两页的根本区别，和两个方案

现网两页的区别不在按钮，在「**点一下格子是什么意思**」：

| | 铺 flow 页（第 1 步） | 押韵页（第 2 步） |
|---|---|---|
| 单击格子 | 点到方格 = 进入改这个方格（打字），点到空白 = 放一个方格（`LyricsGrid.tsx:320` → `flowPick`） | 按选法选格子（`LyricsGrid.tsx:321` → `clickCell`） |
| 双击格子 | 无 | 整格变输入框，改这一拍的字（`LyricsGrid.tsx:355` → `editCell`） |
| 涂色 | 不能 | 选好格子 → 侧栏「涂上X」 |

把两页的按钮堆到一页、点击仍按旧规则分两种，就会出现「同一下点击有时打字、有时选格子」。两个方案：

| | **A 画笔模式（推荐）** | B 选中再改（沿用第 2 步的点法） |
|---|---|---|
| 单击格子 | 看手里拿的工具：打字（默认）/ 涂色 / 选格子 | 永远是选格子 |
| 打字 | 单击方格直接打（v3.2 原样） | 选中后按 Enter 或双击才进入打字 |
| 涂色 | 侧栏点颜色拿起画笔，点 / 拖格子 | 选格子 → 点「涂上」 |
| 好处 | 写词时最常做的打字一下就到；涂色是连续动作（一列 16 格一拖就完）；你 11-18 说「方格已经能打字」，A 保住这一点 | 只有一种点击意思，不需要模式 |
| 坏处 | 多了「模式」，必须让人一直看得出在哪个模式（2.2 节五道提示） | 每打一个字多一下（先选再进入），把 v3.2 刚做好的「点方格打字」退回去；涂一列还是要先选再按按钮 |

推荐 **A**。以下都按 A 写。

### 2.2 手里的四种工具，以及怎么让人一直知道拿着哪一个

| 工具 | 怎么拿起 | 点 / 拖格子 | 怎么放下 |
|---|---|---|---|
| **打字**（默认，空手） | 放下别的工具就回到它 | 点方格 = 改这个方格；点空白 = 按精度放一个方格（v3.2 规则不变） | — |
| **涂色：某种颜色** | 侧栏（手机：抽屉头）点这种颜色的色块；「+」新建颜色后自动拿起 | 点 = 涂这一格；拖 = 画笔经过的每一格都涂；点行头 = 整行；点拍头 = 整列（只涂有字的格） | 再点同一个色块 / Esc / 模式提示上的「完成」/ 切到歌词页 |
| **橡皮** | 色块后面的「擦」 | 点 / 拖 = 擦掉颜色 | 同上 |
| **选格子**（给锁定、AI 用） | 点行头 / 拍头（任何工具下都行，涂色时除外——涂色时点行头是涂整行）；侧栏锁定 / AI 那块的「选格子」 | 点 = 一格；拖 = 一块矩形；Shift+点 = 加上 / 去掉一格；Shift+点行头 = 连续几行 | Esc / 「完成」；放下时选区清掉 |

**模式看得见**（五道，脚本断言前两道）：

1. **工具条最左的模式提示**，永远在（工具条是粘住的，滚到哪都在）：打字 = 白底「✎ 打字 · 点方格写字」；涂色 = **这种颜色的格子底色 + 2px 色块色描边**「🖌 涂色：粉色 · 遥条辙 · 点 / 拖格子上色 · Esc 放下 · [完成]」；选格子 = 强调色「选格子 · 第 13–14 小节 · 8 格 · [完成]」。
2. **整张表外面一圈这种颜色**（涂色时），选格子时指针是十字格。
3. **指针变画笔**（桌面 hover；`cursor: url(data:…)`，不发请求）。
4. **拿起的色块上画一支笔**、按下态；手机抽屉头整条换成这种颜色的底、标题变「涂色」。
5. **涂色时没有光标、不弹软键盘**（没有输入框拿焦点）；打一个字母会出提示条「正拿着粉色画笔，按 Esc（手机点「完成」）回到打字」。

### 2.3 键盘：接在 DESIGN_v32 §3 的状态表上

v3.2 的「改方格」状态（看不见的输入框、空格分格、Shift+空格三连、0.4 秒两下空格变空音、退格清字 / 合并、Tab / 方向键换格、`-` / `=` 拖长、输入法拼字时一概不接）**一行不改**。新加的只有「拿着画笔 / 选格子」两个状态，而且它们**没有输入框拿焦点**，所以键盘事件走全局快捷键（`App.tsx` `useShortcuts`），和改方格的输入框互不相干：

| 状态 | 输入 | 结果 |
|---|---|---|
| 改方格（v3.2） | 全部 v3.2 按键 | 不变 |
| 改方格 | 点侧栏色块 | 先结束改方格（输入法里还没上屏的拼音按浏览器默认在失焦时上屏、写进那一格，算一步），再拿起画笔 |
| 空手（没在改方格） | 空格 | 播放 / 暂停（不变） |
| 拿着画笔 / 橡皮 | 点 / 拖格子 | 涂 / 擦；**一次拖动 = 历史里一步**（松手时 `exec`） |
| 拿着画笔 / 橡皮 | Esc | 放下，回到空手（不进改方格） |
| 拿着画笔 / 橡皮 | 空格 | 播放 / 暂停（和空手一样；不会分格，因为没有方格在改） |
| 拿着画笔 / 橡皮 | 退格 / Delete | **什么都不做**（现网第 1 步空手按退格会删光标字 `App.tsx:90`；拿着画笔时 `cursor` 为空，并显式拦掉，免得误删） |
| 拿着画笔 / 橡皮 | 字母 / 数字 / 输入法 | 不写字；出一次提示条（见上） |
| 拿着画笔 / 橡皮 | Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | 撤销 / 重做，**画笔不放下** |
| 拿着画笔 | 方向键、Tab、Enter、`-` / `=` | 不做事（这些是打字工具的键） |
| 选格子 | Esc | 退出并清掉选区 |
| 选格子 | 方向键 | 选区往那边挪一格（Shift+方向键扩大），和表格软件一样 |
| 任何状态 | 切到歌词页 | 放下工具；回来时是空手 |

- **没有键盘快捷键拿起画笔**：数字键、字母键在改方格时是要写进格子的字，不能借用。拿起只靠点色块（这是有意的：拿画笔是一个看得见的动作）。
- Shift+Enter 不再有特殊意思（v3.3 作废），和 Enter 一样结束打字。

### 2.4 鼠标、拖动

- 涂色拖动：按下的格子开始，**经过的每一格**都算（画笔的意思，不是矩形）；拖的过程中先铺这种颜色的底 + 虚线框（`paint.html`），旁边拖动提示「涂粉色 · 4 格 · 松手算一步」；松手才 `exec` 一次。拖出表格再松手 = 照样涂经过的格子；按 Esc 中途取消 = 一格都不涂。
- 只有拖音 / 没有字的格子照旧涂不上：拖动时跳过，松手提示「涂上 4 格；跳过 1 格（只有拖音）」；单点一格只有拖音的格子出现现网的拖音提示（`hold-tip`）。
- 打字工具下改长度的把手（`grip`）照旧；拿着画笔时把手不显示（不能一边涂一边拖长度）。
- 右键行头的菜单（复制 flow / 清空这一小节 / 删除）任何工具下都在。

### 2.5 手机（没有 Esc、没有 hover）

- **拿起**：点抽屉头（收起时 56px，一直看得见）的色块。抽屉头换成这种颜色的底、标题「涂色」，色块上画笔。
- **放下**：点工具条模式提示上的「**完成**」（手机上 36px 高，脚本断言 ≥ 36px）或者再点一次同一个色块。
- **涂和滚的冲突**：拿着画笔时格子区域 `touch-action: none`，**一指涂、两指滚**；左边小节号那一列仍然可以一指上下滑（`touch-action: pan-y`）。模式提示里写「一指涂 · 两指滚」。空手时一指照常滚动、点方格弹键盘。
- 涂色时没有输入框拿焦点，所以**软键盘自动收起**——这本身就是手机上最明显的模式提示。
- 抽屉头放不下「6 种颜色 + 擦 + + + 上滑展开」（检查脚本实测「+」被裁掉，现网颜色一多也会这样）：「上滑展开」只留箭头图标（`aria-label` 照旧写字）。

### 2.6 撤销 / 重做

**仍是一条单线历史**（DESIGN_v3 拍板题 8、v3_impl §4）。一次涂色拖动、一次擦、改押数 / 韵母、改判押韵档、锁定，各算一步；**拿起 / 放下工具、选格子不进历史**（和现在切步骤、选格子一样是界面状态）。撤销后工具不变。

## 3. 「歌词」展示页

### 3.1 布局

- 页签：`写词 | 歌词`（就是现在的步骤切换那一组，第 2 个从「填字和韵脚」改成「歌词」）。
- 工具条：**复制全部**、**导出 .txt**、字号 小 / 中 / 大、**跟随播放**（开关，默认开）、「正在唱：Hook A 1 第 3 行 · 第 28 小节」。
- 正文居中一栏（最宽 680px）：段落标题（Verse 1 / Pre-Hook 1 / Hook A 1 …，**用作品里的段落名原样**，所以 Pre-Hook、Interlude 这种不在五种类型里的名字也照写）+「8 行」；每行左边小号写小节号（`02`），右边是这一行的字。
- 侧栏（桌面）：韵脚颜色图例（蓝色 言前辙 32 处 …）、分行说明 +「调整分行」、提词说明。手机没有侧栏，抽屉头是颜色图例。

### 3.2 「一句」怎么切

**默认一小节一行**（和现在 `exportTxt` 一样，`project.ts:456`；没有字的小节跳过）。v4 里 123 小节、122 行，和你的 `koi_zh_lyrics_v4_nopickup.txt` 逐行对得上（脚本逐字比了每一行）。

| 节奏 | 一小节一行时的样子 | 处理 |
|---|---|---|
| 一句一小节（v4 全部） | 正好一句一行 | — |
| 一句跨两小节 | 断成两行，第二行接着上一句 | 「调整分行」→ 点两行之间 = **并成一行** |
| 半小节一句（一小节两句，快嘴段） | 两句挤在一行 | 「调整分行」→ 点第二句第一个字 = **从这个字起另起一行** |
| 抢拍（下一句第一个字在上一小节第 4 拍后半） | 这个字挂在上一行末尾 | 同上，在这个字上拆行 |

**推荐做「调整分行」，但只影响展示**：歌词页、复制、导出 txt / LRC 用它；押韵、涂色、表格、AI 都不看它。

- 存：`lyricLayout: { join: barId[], split: wordId[] }`——`join` 里的小节接在上一行后面；`split` 里的字从它起另起一行。挂在小节 id、字 id 上，插删小节、分格不用重算；读的时候指向不存在的 id 丢掉。
- 操作：点「调整分行」进入分行状态（工具条出现「完成」），两行之间出现「并成一行」的细条、点字出现「从这里拆行」；每一下是历史里一步；手机同样（点细条 / 点字）。
- 为什么不自动：v3.3 实测只看节奏猜句子准确率 62%、召回 32%，猜错比不猜更糟；默认一小节一行在 v4 这种写法下是对的。

### 3.3 空行、空音、空方格、字号

- 段落之间空 16px；段落里一行没有字（例如 Intro）→ 写一行灰字「（1 小节伴奏）」，不算行数。
- **句内空音 ≥ 半拍**：留 0.5 个字宽的空隙（v4 里 16 处，例如「嗨 怎么你也在这边」「不怕路再远 不怕风雨再猛」）；< 半拍不留。空隙不是字符，**复制和导出不带空格**（和现在的 `exportTxt` 一致，不改导出格式）。
- 还没写字的方格：显示一条浅灰短横「_」（和旧第 2 步「空字画一条下划线」同一个意思）；复制 / 导出时跳过。
- 字号：桌面 16 / 20 / 24px（默认 20），手机 15 / 17 / 20px（默认 17），行高 1.7。韵脚字加粗、用写词页同一个颜色公式 `hsl(色相 ink-s ink-l)`——脚本把歌词页每个韵脚字的颜色和写词页同一种颜色的韵脚字**逐个比，完全相等**。

### 3.4 跟着播放高亮（提词器）

- 当前行 = 起点 ≤ 播放头的最后一行（两行之间的空拍里保持上一行）；整行垫强调色浅底 + 左边 3px 强调色竖条，正在唱的那个字下面画强调色线。
- 跟随播放开着时，当前行自动滚到屏幕上 1/3 处；你自己滚动后 3 秒内不抢回来（工具条「跟随播放」变成没按下，点一下回去）。
- 点一行 = 从这一行第一个字开始播（空格照常播放 / 暂停）。

### 3.5 复制 / 导出

- 复制全部 = `exportTxt` 的文字（有 `lyricLayout` 时按它分行）写进剪贴板，提示「已复制 122 行歌词」；剪贴板不让写时弹出一个可以全选的文本框（和导出面板「从下面复制」同一种做法）。
- 导出 .txt = 同一份文字下载成「作品名.txt」。LRC 仍在「作品与导出」面板。

### 3.6 手机

一栏铺满，左边小节号 24px 宽、10px 字；工具条一行放下「复制全部 / 导出 .txt / 小中大 / 跟随播放」（量过不溢出）；当前行同样滚在上 1/3 处；抽屉收起只显示颜色图例。

## 4. 押韵判断改十三辙

### 4.1 为什么（实测，pinyin-pro 3.29.5，和 App 一样逐字取韵母）

| 作品 | 规则 | 严格韵母判「不押」 | 十三辙判「不押」 |
|---|---|---|---|
| 你的 v1（58 格涂色，6 种颜色一色一条规则） | 蓝 an、绿 ong、粉 ao、金 ing、青 ei、草绿 i | **19 / 58**：转 环 完 uan、边 连 ian、梦 eng、随 水 退 悔 ui、笑 iao | **0** |
| v4 的词，如果每种颜色只建一条规则 | 蓝 an、绿 ong、粉 ao、金 ang、青 ei、草绿 i | **56 / 117**：蓝 20（ian / uan / üan）、粉 13（iao）、金 10（iang / uang）、绿 8（ing / eng）、青 5（ui） | **0** |
| v4 文件本身 | 15 条规则：同一种颜色拆成 ian / an / üan / uan 四条…… | 0（为了绕开严格判韵才拆的） | 0；按辙合并后是 **6 种颜色** |

v4 文件那种「一种颜色拆成 4 条规则」本身就说明严格判韵不合用：色块面板上会出现 15 个色块、好几个同色。

### 4.2 辙表（来源与全表）

来源：传统北方曲艺 / 京剧的十三辙（发花、梭波、乜斜、一七、姑苏、怀来、灰堆、遥条、由求、言前、人辰、江阳、中东），是中文说唱、流行歌词最通行的韵部划分。**代码里已经有这张表**：`src/core/rhyme/syllable.ts` 的 `FINAL_TO_GROUP`（第一期按十三辙给句尾着色时用的，`RHYME_MATCH_MODE = 'loose'` 也是它），本稿不新造表，稿子 `v34.js` 和检查脚本各抄一份逐字一致。

| 辙 | 韵母 | 例字（括号里是 v4 用到的位置） |
|---|---|---|
| 发花 | a ia ua | 花 家 夸 |
| 梭波 | o e uo | 波 歌 多 |
| 乜斜 | ie üe ê | 街 月 写 |
| 一七 | i ü -i（zhi chi shi ri zi ci si 的 i）er | 季 丽 起 记 迹（Verse 3 全部） |
| 姑苏 | u | 路 苦 |
| 怀来 | ai uai | 来 怀 |
| 灰堆 | ei ui（uei） | 惫 累 泪 / 罪 贵 灰 追 碎（Bridge） |
| 遥条 | ao iao | 跑 闹 宝 老 / 跳 掉 笑 摇（Hook A） |
| 由求 | ou iu（iou） | 走 / 求 |
| 言前 | an ian uan üan | 半 讪 / 边 天 面 / 弯 转 完 / 眩 圈 愿 远（Verse 1、Hook B） |
| 人辰 | en in un（uen）ün | 人 / 心 / 春 / 云 |
| 江阳 | ang iang uang | 旁 膀 / 香 讲 凉 / 晃 光 忘 闯（Verse 2） |
| 中东 | eng ing ong iong ueng | 梦 声 猛 / 停 景 星 / 动 空 懂（Pre-Hook） |

### 4.3 y / w 开头的字、pinyin-pro 拆出来的韵母怎么归一

pinyin-pro 给的是整个音节（`yao`、`yuan`、`wan`），**先还原成标准韵母再查辙**（`splitSyllable`，`syllable.ts`；规则：y/w 零声母查 `Y_FINALS` / `W_FINALS` 表；j q x 后面的 u 是 ü；iou → iu、uei → ui、uen → un；zh ch sh r z c s 后的 i 记作 -i）。逐字实测：

| 字 | pinyin-pro | 还原成 | 辙 | 严格档里它算什么 |
|---|---|---|---|---|
| 摇 | yao | iao | 遥条 | iao（≠ ao） |
| 愿 | yuan | üan | 言前 | üan（≠ an / uan） |
| 远 | yuan | üan | 言前 | üan |
| 弯 | wan | uan | 言前 | uan（≠ an） |
| 完 | wan | uan | 言前 | uan |
| 忘 | wang | uang | 江阳 | uang（≠ ang） |
| 月 / 略 | yue / lüe | üe | 乜斜 | üe |
| 云 | yun | ün | 人辰 | ün |
| 用 | yong | iong | 中东 | iong |
| 翁 | weng | ueng | 中东 | ueng |
| 儿 | er | er | 一七 | er |
| 日 | ri | -i | 一七 | 字面 i |

所以「摇、愿、远、弯、完、忘」在严格档里各自只押自己那个带介音的韵母，在十三辙里都回到该押的辙。规则框里你写 `yuan`、`v`（= ü）、`ian` 也一样先还原（`normalizeFinal` + `splitSyllable`），写辙名「言前」直接认。

### 4.4 前后鼻音 in / ing 同不同辙

**推荐：不同辙**（in 属人辰，ing 属中东，照十三辙原表）。依据：

1. 十三辙本来就把前鼻音（en in un ün）和后鼻音（eng ing ong iong）分成两辙。
2. v4 里以 ing 收尾的 3 句（停 / 景 / 星）全是和 ong / eng 押（Pre-Hook 的中东辙），**没有一句以 in / en / un 收尾**——并成一辙对这首歌没有好处。
3. 只把 in 和 ing 并起来会破坏「同辙就押」的传递性（心~星、星~东，那心~东算不算？）；要并就只能把人辰、中东整辙合并，那「人 / 心 / 风 / 东」全算押上，判韵太松，「对不上」提示基本失效。
4. 南方口音前后鼻音不分的押法很常见，但那是**有意放宽**，应该由你选，不该是默认。拍板题 Q5 给了「再加一个『宽』档（人辰 + 中东合并）」的选项。

### 4.5 「严格韵母」要不要留

**推荐留，作为作品级的第二档**（右栏「判押韵：十三辙 | 严格韵母」）：

- 旧作品打开时需要它（不然打开就变样，见 4.7）；
- 双押、四押想抠到介音一致时有用；
- 代码里本来就是 `'strict' | 'loose'` 两档（`rhymeRules.ts:37`），只是从「改代码的常量」变成「存在作品里、界面能切」。

### 4.6 规则、合并、候选、占位在十三辙下怎么算

- 规则还是 `{ count, finals[] }`，**finals 存你写的样子**（`an`、`ian`、`言前` 都行），不改写；判的时候按作品的档解释：十三辙 = 查辙，严格 = 比字面。这样切回严格档不丢信息。
- 「两种颜色同韵自动合并」（v3_impl §4）的「同韵」跟着档走：十三辙 = 每一位同辙。改档、改韵母时触发合并，和现在一样「改和合并算一步」，提示写「绿色（ian）和蓝色（an）都是言前辙，已合并成蓝色（12 格从绿变蓝），可以撤销」。
- 候选（`ruleCandidates`）、`finalsMatch`、`rhymeSlots`、`mismatches`、行尾标签、AI ④：**全部改成传作品的档**，不再读代码常量 `RHYME_MATCH_MODE`。候选里同辙内韵母完全相同的排前面（`localMatches` 已经这样排）。
- 空着的韵脚位占位：十三辙写辙名（「言前」），严格写韵母。

### 4.7 旧作品已有的规则怎么迁移（不能悄悄变色）

- 作品里**没有 `rhymeMatch` 字段 = 旧作品 → 按严格打开**，画面、颜色、「对不上」和以前完全一样。
- 顶上一条迁移横幅（`rhyme13.html`，和「清空全部 flow…」就地确认同一种样子）：「这个作品按旧规则判押韵（韵母一字不差）。改成十三辙：全曲 56 处『不押』会消失，格子颜色不变。可以撤销。」+「改用十三辙」「先不改」。横幅里的数字现算：
  - 「不押」少几处；
  - 有没有颜色要合并、合并后哪些格子变色（同色相的合并颜色不变——v4 文件就是这种：15 条规则 → 6 种颜色，格子一个都不变色；**不同色相合并会变色时，逐条写出「绿色并进蓝色：12 格从绿变蓝」**）。
- 「改用十三辙」= 历史里一步（改档 + 合并），撤销一次回到原样。「先不改」= 在作品里写下 `rhymeMatch: 'strict'`（一步），以后不再问；右栏随时能切。
- 新建作品、示例作品默认十三辙。

## 8. 拍板题

**Q1 两页怎么合？**
- A（推荐）画笔模式：默认打字，侧栏点颜色拿起画笔涂，Esc / 再点 / 完成放下。B 选中再改：单击永远选格子，Enter / 双击才打字。
- 依据：A 保住 v3.2「点方格就打字」，涂一列一拖就完；B 每打一个字多一下。A 的代价是有模式，用五道提示解决（2.2 节）。

**Q2 涂色拖动是「经过的格子」还是「矩形」？**
- A（推荐）经过的格子（画笔）。B 矩形（表格软件的框选）。
- 依据：押韵最常见是一列（第 4 拍往下拖）或一行，两种一样；斜着拖时 A 符合「画笔」直觉，矩形会把中间不想要的格子也涂上。要矩形用选格子工具。

**Q3 双击改一拍（打 3 个字自动变三连）删不删？**
- A（推荐）删，用 Shift+空格分三连再打。B 留一个捷径：输入法一次上屏 N 个字、这一拍只有一个空方格时自动平分。
- 依据：A 只有一种打字方式；B 会让「打字顺便改了节奏」，和 v3.2「分格靠空格」的规矩打架。

**Q4 判押韵默认哪一档？**
- A（推荐）十三辙，严格作为第二档。B 十三辙，不留严格。C 维持严格。
- 依据：你实测 19/58 误报；v4 一色一规则时 56/117。留严格给旧作品和抠介音的双押用，成本只是一个两档按钮。

**Q5 前后鼻音 in / ing？**
- A（推荐）不同辙（十三辙原表）。B 同辙：再加第三档「宽」（人辰 + 中东整辙合并），作品自己选。
- 依据：4.4 节。v4 里没有 in / ing 互押的句子，A 对这首歌零损失；B 以后需要时加一档即可，数据不用变。

**Q6 旧作品打开时怎么办？**
- A（推荐）还是严格 + 迁移横幅（写清少几处不押、哪些颜色合并 / 变色），点了才改，一步可撤销。B 自动改成十三辙，弹一条提示可撤销。
- 依据：A 打开文件不改文档（和 v3 迁移「等你第一次改动才写」一致）；B 会在你没动手的时候改掉作品、触发自动保存。

**Q7 歌词页要不要「调整分行」？**
- A（推荐）做，只影响歌词页和导出，放最后一段实现。B 不做，永远一小节一行。C 自动按节奏猜。
- 依据：v4 用不上，但别的歌有跨小节句 / 一小节两句 / 抢拍；C 实测猜不准（v3.3：准 62%、召回 32%）。

**Q8 歌词页句内空音怎么显示？**
- A（推荐）≥ 半拍留半个字宽的空隙，复制 / 导出不带空格。B 显示成空格，导出也带。C 不显示。
- 依据：A 看得出换气、导出和现在 `exportTxt` 一样；B 会改掉现有导出格式。

**Q9 锁定 / AI 的选区用什么？**
- A（推荐）第三种工具「选格子」（点行头 / 拍头自动拿起，点 / 拖 / Shift）。B 打字工具下 Shift+拖 = 框选，不另设工具。
- 依据：A 手机上也能用（手机没有 Shift）；和画笔同一个「拿起 / 放下」模型，不多一个概念。
