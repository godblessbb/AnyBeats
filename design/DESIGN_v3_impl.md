# AnyBeats v3 实现说明：和视觉稿对不上的地方

> `design/DESIGN_v3.md` 和 `design/mockups_v3/` 不改。实现时按用户 11-16 的决定改掉的地方、视觉稿没画到而由实现自己定的地方，都记在这里。
> 补充视觉稿：`design/mockups_v3b/`（drag / wrap / dense 三个画面），截图 `design/screenshots_v3b/`（3 画面 × 桌面 1280 / 手机 390 × 浅 / 深 = 12 张），
> 自检 `python -I design/check_mockups_v3b.py design`，反向探针 `evidence/ct_6765fa8b/negative_checks_v3b.md`。
> 产品检查：`python -I e2e/check_app_v3.py dist/index.html`（在构建产物上实测），反向探针 `evidence/ct_6765fa8b/negative_checks.md`。

## 1. 拖音 = 字的长度（作废 DESIGN_v3 第 1 节的 SlotKind 'hold' / 'rest'）

- 数据里只有字：`Word { id, tick, len, text }`（`src/core/grid.ts`），tick 是这一小节里的起点（0–191），len 是持续多少 tick（每拍 48），可以拖过格线、拖过小节线。`text` 可以先空着（只铺 flow 不填字）。
- **空音 = 字和字之间留出的空白**，不存、不画框。v3 的「空音虚线灰底框」「拖音实心横条」两种字格都不再出现。
- 画法：每个字画成「字框 + 细线」。字框那一段的长度 = `min(len, U)`（`core/flow.ts` 的 `boxTicks`）：
  - 落在 1/32 半格上（tick % 12 = 6）的字 U = 6；
  - 半拍三连那一拍 U = 8，三连那一拍 U = 16；
  - 其余 U = 12（一个 16 分）。

  超出字框的部分画成字后面一条**同色细线**，画到字结束的 tick：可以越过格线；拖过一行末尾就接着画在下一行第一格开头（`drag.html` ①–④）。
  线色跟字走：没涂色 = 字的颜色；还没填字 = 字框线色；韵脚字 = 这一格涂的颜色。
- 跨格的字**归属它起点所在的格**：涂色、押数、锁定都按起点那一格算（`drag.html` ③：第 5 小节第 2 拍绿色的「拍」拖进第 3 拍，线还是绿色）。
- **只有拖音、没有新字的格子不能涂色**：点它出提示「这一拍只有拖音」，说明是哪个字拖过来的（`drag.html` ⑤）。整行 / 整列涂色时这种格子跳过，提示「跳过 N 格」。
- 押数只数字，不数拖的长度：「路口——」拖进下一行还是双押。
- 铺 flow 时拉长：拖字框右边缘（停在哪一格的哪个位置就拖到哪里，吸附到精度）；或选中后按 `-`，每按一次多拖一个精度单位；`=` 缩回一个单位；`⌫` 删掉字，留下的就是空音。拉长不挪后面的字，最多拖到下一个字的起点。

## 2. 一句超过一小节（推翻执行者旧决定 2：不标「续」）

- 表格一行 = 一小节，列 = 1–4 拍。一句话超过一小节，超出的字就排在下一行（下一小节）开头；行头照常写小节号，**不标「续」，也不加别的续行标记**（`wrap.html`）。
- 下一句可以从同一行中间开始（`wrap.html` 第 5 小节第 3 拍），列头上下对齐不变。数据里不另存「句」。

## 3. 手机 390 宽的最小字宽（`dense.html`，第二段按用户回答改过）

390 宽一拍格宽 85px，字框 = 字占的 tick ÷ 48 × 格宽 − 2px 间隙。字号按浏览器量出来的格宽现算（`core/flow.ts` 的 `wordSize`，`LyricsGrid` 用 ResizeObserver 量格宽）：

| 落点 | tick | 手机 390 字框 | 手机上怎么排 | 桌面 1280 |
|---|---|---|---|---|
| 1/16 | 12 | 19.3px | 字 15px，照常 | 40px · 19px |
| 三连 | 16 | 26.3px | 字 15px，照常 | 54px · 19px |
| 半拍三连 | 8 | 12.2px | 字缩到 11px，去掉边线改浅底 | 26px · 19px |
| 1/32 | 6 | 8.6px，放不下 | **整张表左右滑**：每拍放宽到 112px（格子里面），1/32 字框 12px、字 11px | 19px · 17px，并排，不滑 |

规则：字号 = 字框里放得下的宽度，最大 15px（桌面 19px），**最小 11px**；放不下 11px 先去边线（多出 2px）；还放不下（只有 1/32）就**整张表左右滑**（`core/flow.ts` 的 `minCellWidth`：1/32 要 112px、半拍三连要 84px）。左右滑时行头、表头角贴在左边，列头跟着一起滑、上下对齐不变。作品里没有 1/32 就不滑。
第一段视觉稿里画的「1/32 两个字上下叠」被用户否掉（11-16 回答：「手机 1/32 别上下叠，改成整张表可左右滑」），`dense.html` 已经改成左右滑的样子。

## 4. 按 11-16 决定改掉的视觉稿 / 旧决定

- 韵母比对严格按字面，不忽略介音（iang ≠ ang、uan ≠ an），是一个设置常量 `RHYME_MATCH_MODE`（`core/rhymeRules.ts`），默认 `'strict'`，改成 `'loose'` 就按十三辙（推翻 DESIGN_v3「忽略介音」和执行者旧决定 5）。
  「字面」按拼音写法：zhi / chi / shi / ri / zi / ci / si 的韵母字面是 i，所以「是」押 i；you 是 iu。
- 两种颜色定成同一个韵（押数和韵母串都一样）时自动合并：留先建的颜色，另一种的格子全部改成它。**改规则和合并算同一步**，撤销一次回到改之前（两种颜色、原来的涂色和韵母都回来）。韵母还空着的规则不参与合并。
- 不保留 v2 的「和上句不押」提示，只提示「对不上本格颜色」（行尾标签 + 押韵面板列表，手机抽屉把手写「N 处对不上」）。
- 换伴奏 BPM 不同时，弹窗**默认推荐「改用新 BPM」**：这个选项有朱橙描边和「推荐」字样、打开时默认聚焦（回车就选它）（推翻视觉稿 `beat.html` 和执行者旧决定 13）。
- 段落标签英文：Intro / Verse / Hook / Bridge / Outro；段落菜单里只能在这五种之间改，同类有好几段时自动编号（Verse 1、Verse 2），不再给自由改名。
- 撤销 / 重做单线：撤销后做新改动就丢掉可重做的步骤；填字、铺 flow、涂色、锁定、换伴奏（含 BPM 二选一）都走这一条；历史随作品存进本机，刷新后还在。

## 5. 视觉稿没画到、由实现定的

### 数据与存储
- 涂色、锁定里的格子用「小节 id:拍」做键，插删小节后不串格。存盘前会清掉指向已删小节 / 规则、或已经不能涂的格子的条目。
- **一个字都没铺的空格子也不能涂色**（视觉稿只说了只有拖音的格子）：没有字就没有韵脚位置，涂上也没意义。
- 撤销历史单独存在 `anybeats.history.v3.<作品 id>`，和作品同时写（防抖 1 秒、关页面立即写）。最多 200 步；序列化时每个快照拆成「元数据 / 规则 / 涂色 / 锁定 / 段落骨架 / 每个小节」，所有快照共用一张去重的字符串表，所以存 200 步只比一份作品大几倍；超过 150 万字符从最早的步骤开始丢，当前状态一定保留。读回时如果历史的当前状态和作品正文对不上（例如历史没来得及写），就从头开始一条新历史，作品照常打开。
- 锁住的字不能改：每一步改动先逐字比对，碰到锁住的格子 / 锁住的韵脚字整步不做并提示。锁定操作本身不受限；删掉含锁定格子的小节也会被拦下。

### 存量作品迁移（PROJECT_VERSION 2 → 3）
- 键沿用第一期：`anybeats.project.v2.<id>`（正文）、`anybeats.library.v2`（索引）、`anybeats.current.v2`。第一次读到旧版本（v1 / v2 / 认不出的版本）时，原文原样拷到 `anybeats.backup.v2.<id>`；备份已经有了就不覆盖，删除作品时也不删备份。
- 迁移失败（JSON 坏了、每小节不是 16 格、版本号更新）：返回读不出，**正文和备份都原样留着**，换一个能读的作品打开并提示「原文已保留在本机」。迁移成功后，正文要等用户第一次改动才写成 v3。
- 换算：1/16 起点 × 12 = tick；片段长度 × 12 = 字长；hold 片段并进前一个字的长度（前一个字正好在这里结束才并，可以跨小节、跨段落）；前面是空拍或在开头的 hold 丢掉；空拍片段变成空白；一个片段里有几个字就按时长平分成几个字（例如一个 16 分里两个字 → 两个 1/32）；重音这一版不用，丢掉（原文在备份键里）。
- 段落名：前奏 → Intro、主歌 N → Verse N、导歌 → Bridge、副歌 → Hook、桥段 → Bridge、尾奏 → Outro；没带号的同类段落按顺序编号。v1（旧界面 `anybeats_projects`）先转成 v2 再走同一条迁移。
- 单测：`src/core/__tests__/project.test.ts` 用第一期代码（提交 f90ef34）原样生成的 v2 夹具（`fixtures/v2project.ts`）证明字、落点、长度、段落、小节 id 都对得上；`src/storage/__tests__/storage.test.ts` 证明备份和失败不丢数据；e2e 第 11 条在浏览器里再验一遍。

### 落点精度
- 精度多了一种「半拍三连」（一拍 6 个，每个 8 tick），手机最小字宽方案里用到。精度是界面状态，不存进作品。

### 换伴奏
- 只有「新伴奏 BPM 和工程不一样，而且作品里已经铺了字」才弹窗；新作品（一个字都没有）直接改用新 BPM。检测出的 BPM 离整数不到 0.15 就取整，否则保留一位小数。
- 「保留原 BPM」：伴奏按 `工程 BPM ÷ 伴奏 BPM` 变速播放（`BeatRef.rate`）；「改用新 BPM」：工程 BPM 改成新的，伴奏原速。两种都只改秒数，字的 tick 不动。
- 新伴奏的首拍（按检测出的 BPM 找起音最强的相位）自动对齐第 1 小节，写进第一拍偏移。
- 音频本身不存进本机（和第一期一样）：刷新后伴奏轨显示文件名和「需要重新选择文件」，再选同一个文件不算换伴奏、不弹窗。撤销 / 重做换伴奏时，这次打开里载入过的音频会跟着切回去。

### 导唱
- 顶栏「导唱」开关：每个字「嗒」一声（三角波，起音后保持到字结束），按字的长度拉长，空白不出声；在时钟的每个 16 分里按 tick 精确排进去，三连、1/32 也准；和伴奏、节拍器共用一个 AudioContext 时钟。导出 Reaper 工程时导唱分轨也按字的长度渲染。
- 视觉稿 `flow.html` 里画在伴奏轨下面的「导唱轨」（标着「后续实现」）这一版没画成可见的轨道，只做了声音。

### 录音、AI
- 录音整块不挂载：构建开关 `VITE_ANYBEATS_RECORDING=1` 才在 `main.tsx` 里创建 RecordController、在右栏挂 RecordPanel；默认构建里这段代码被整段裁掉（`src/audio/*`、`RecordPanel.tsx` 原样保留）。
- AI 不挂载：构建开关 `VITE_ANYBEATS_AI=1` 才创建 AiController；静态版没有 AI 入口、没有 Worker 文案。一次填韵和选区润色的逻辑在 `src/core/aiEdit.ts` + `src/core/locks.ts`（有单测），`src/engine/aiController.ts` 接 AiProvider。旧的 AI 面板（续写 / 改押韵 / 调字数）和旧押韵面板随旧流程删掉。
- **一次填韵**按字面理解「只填空位、跳过已写字的格子」：涂了色的格子里只要有一个字写了字，整格跳过；锁住的韵脚位置也不填。AI 的回答只要写到别的位置，整份作废。
- **选区润色**：默认保持骨架（字数、落点、长度都不变，只换字）；打开「允许改 flow」就不再保持骨架，可以在选区内增减字、挪落点。结果逐字比对，选区外或锁定位置有任何改动就整份作废。

### 界面
- 第二步里点字直接进入填字（单格选法时）；回车填完自动跳到下一个字继续填，一次打多个字会依次填进后面的位置。
- 「作品」「导出」两个按钮都打开右栏（手机是抽屉）里的「作品与导出」面板：作品列表（新建 / 另存为 / 导入 / 改名 / 删除 / 示例）+ 导出（txt / LRC / 工程文件 / Reaper 工程）。
- 列头的小刻度点了以后，整首这一列（这一拍的第几个 16 分）用两条朱橙竖线框出来，再点一次取消。
- 手机底部抽屉在「铺 flow」步骤里放精度，在「填字和韵脚」步骤里放色块；点「锁定」时抽屉自动拉开显示锁定面板。
- 旧 e2e（`e2e/smoke.py`、`negative_checks.py`、`ai_preview_shots.py`）驱动的是旧界面（1/16 格、AI 面板、录音键），跑不了，删掉，由 `e2e/check_app_v3.py` 取代；`e2e/negative_checks_audio.py` 只改音频代码跑 vitest，保留。
