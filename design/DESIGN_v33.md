## 0. 一页结论

1. **数据**：句尾是挂在「这一句最后一个字」上的一个标记 `Word.brk = 'end' | 'guess'`（确认过 / 自动猜的待确认），**句首不存**——上一个句尾后面的第一个字就是句首。不加独立的句子表。拖音、三连、1/32、跨小节、一小节多句都不用特殊处理，因为标记跟着字走。
2. **兼容**：没有 `brk` 的作品 = 「还没断句」，打开后**和 v3.2 一模一样**（不画括线，涂色规则一个字都不变）。`.anybeats` 还是第 3 版，字上多一个可选字段，没有就不写。
3. **显示**：一句 = 方格下面一条括线 └────┘，句首深色竖线、句尾红竖线、中间横线连着，相邻两句横线一深一浅；待确认 = 虚线；桌面句首旁写这一段第几句。两句紧挨着时红线和深线并排各 3px，量过不重叠（一小节 4 句、1/32 也一样）。
4. **手动标**：光标在方格上按 **Shift+Enter** = 这一格是句尾 / 再按取消（拆句、合句、取消都是它）；鼠标点两格之间的缝 = 在这里断开；拖红线 = 挪句尾；触屏点红线出小菜单。每一下都是单线历史里的一步。原有方格快捷键（空格 / Shift+空格 / 两下空格 / 退格）不变。
5. **自动断句**：(a) 从歌曲提取 flow 时按歌词断句，直接写成确认过的句尾；(b) 只有 flow 时按「空白 ≥ 半拍或段落交界」猜，**全标待确认**。(b) 在这首歌上实测：猜 60 处、对 37 处（准 62%），116 句只找到 37 句的句尾（**召回 32%**）；第 99–110 小节 12 句一处都猜不出来。界面明说「快嘴段会漏」，并在连续 ≥ 4 小节没有断点的地方插提示。**(b) 不可靠，只是起点。**
6. **韵脚默认落句尾**：涂色数据不变（还是一格一种颜色）。变的是「涂了色的格子押哪几个字」：**这一格里有确认过的句尾 → 押这一句的最后 n 个字**（可以跨到前一格、前一小节，但不越过句首）；没有句尾 → 和 v3 一样押格内最后 n 个字。第 2 步新增「句尾」涂法（有断句时默认）：点一句里任何一个字 = 涂这一句句尾所在那一格。单格 / 整行 / 框选照旧，句中韵用单格涂。
7. **AI 约束**：加**第 ⑤ 道程序检查「句子边界」**（句子数和范围不变、句尾标记 AI 不能动、每句的字只落在本句、一个词不跨句尾）；「句尾放押韵字」不另起一道，并进 ③（填韵目标改成句尾韵）和 ④（押韵比对的位置改成句尾锚定），判定函数不变。有待确认的断句时 AI 不开工。
8. **韵脚间隔**：推荐做，第 2 步行尾写「距上一个同色句尾韵几拍」，只提醒不判错（第 8 节）。
9. 拍板题 10 道（第 9 节），和 v3 / v3.1 / v3.2 / AGENT_DESIGN 的冲突 12 处逐条写了去向（第 10 节）。

## 2. 数据模型

### 2.1 选型

| 方案 | 存什么 | 好处 | 坏处 |
|---|---|---|---|
| **A（推荐）句尾标记挂在字上** | `Word.brk?: 'end' \| 'guess'` | 跟着字走：插 / 删小节、复制一行 flow、分格合格都不用重算位置；撤销历史自动带上（它就是表格的一部分）；旧作品没有这个字段 = 没断句 | 句首要现算（上一个句尾后面第一个字）；「空音上的句尾」表达不了（也不需要：句尾一定是一个字） |
| B 独立的句子表 | `phrases: { start: {barId,tick}, end: {barId,tick} }[]` | 句首句尾都显式 | 字被删、被分、被挪时端点可能落在空白上，要一套修复规则；两份数据要保持一致；和 `paint` 一样要做 prune |
| C 断点表 | `breaks: absTick[]` | 最省 | 绝对 tick 一插小节就全错位；和 B 一样有落在空白上的问题 |

### 2.2 定义（实现单写进 `core/phrases.ts`）

```ts
interface Word {
  id: string; tick: number; len: number; text: string;
  /** 这个字是一句的最后一个字。'end' = 确认过；'guess' = 自动断句猜的，待确认。没有 = 不是句尾 */
  brk?: 'end' | 'guess';
}

interface Phrase {            // 现算，不存
  words: WordLocation[];      // 按全曲顺序
  startAbs: number;           // 第一个字的起点
  lastAbs: number;            // 最后一个字的起点（句尾韵从这里往前数）
  endAbs: number;             // 最后一个字的结束（含拖音）= 红竖线的位置
  state: 'end' | 'guess' | 'open';   // open = 全曲最后一个句尾之后还没收尾的字
  section: number;            // 句首所在段落；序号按段落从 1 数
}
function phrases(grid: Grid): Phrase[];   // 全曲扫一遍：遇到 brk 就收一句；一个 brk 都没有 → 返回 []（= 没断句）
```

- **句子 = 两个句尾之间的字**。句首不存，上一个句尾后面第一个字就是句首，所以不会出现「有句首没句尾」「两个句首挨着」这种坏数据。
- 句子之间的空音不属于任何一句（括线在那里断开）；句子里面的空音属于这一句（括线连着画过去）。
- 段落：句子可以跨段落（极少见，不禁止）；序号按**句首所在段落**从 1 数。段落交界在自动断句里一律当断点（第 5 节）。
- 一首歌里一个 `brk` 都没有 = **还没断句**：`phrases()` 返回空，界面不画括线，涂色规则完全按 v3（第 6 节）。只要有一个句尾，最后一个句尾之后的字就是一句「未收尾」（虚线横线，没有红线）。

### 2.3 各种节奏怎么表达（稿子里都有实例）

| 情况 | 怎么存 | 稿子 |
|---|---|---|
| 一小节多句（快嘴） | 一小节里几个字带 `brk`，一句可以只占半拍 | `dense` 第 101、105 小节；S1 一小节 4 句 |
| 跨小节长句 | 句尾在后面某一小节的字上；中间几小节没有标记 | `phrases` 第 20–21、24–25 小节 |
| 三连 | 三连里任何一个字都可以是句尾（16 tick 的字带 `brk`） | `dense` S2 第 1 拍：第 2 个三连后断 |
| 1/32 | 6 tick 的字带 `brk` | `dense` S2 第 3 拍 |
| 拖音 | 标在拖长的那个字上；红线画在**拖音结束处**（字的 `tick + len`），可以在下一拍、下一小节 | `phrases` 第 18 小节第 4 拍 |
| 句尾后面紧接下一句（没换气） | 下一句第一个字起点 = 上一句结束，红线和深线并排 | `dense` 第 101 小节第 1 拍、S1 |

### 2.4 现有编辑操作碰到句尾标记怎么办（都只动标记，不动别的）

| 操作 | 规则 |
|---|---|
| 一分为 n（`splitSquare`） | 标记跟着**最后一块**走（和 v3.2「拖音跟最后一块」同一个道理：句子结束的位置不变） |
| 合并（`mergeSquare`） | 两块同一句 → 合出来的字带左右两块里的标记（右块的）；**两块分属两句（左块带 `brk`）→ 不合**，提示「这两格分属两句，先合句（Shift+Enter 取消句尾）」 |
| 变成空音（`restSquare`） | 被删的字带 `brk` 且同一句里还有前一个字 → 标记挪到前一个字上（这一句少一个字，仍然在这里收尾）；它是这一句唯一的字 → 这一句消失 |
| 空音上放回方格（`fillRest`）、点空白放字 | 新字不带标记；落在两句之间的空白里时归**后一句**（成为后一句的新句首），因为句首是「上一个句尾后面第一个字」 |
| 第 2 步打字重排一拍（v3.1 `setBeatText`，N > S 平分重排） | 这一拍里有句尾、而且句尾**不是**这一拍最后一个字 → 不重排，提示「这一拍里有句尾，重排会把两句搅在一起；先到第 1 步调方格」（和「有锁住的字不重排」同一种处理）。句尾是这一拍最后一个字 → 重排后标记给新的最后一个字 |
| 拖长 / 缩短（`resizeWord`、`-` / `=`） | 标记不动；红线跟着拖音结束处走 |
| 插 / 删小节 | 跟着字走；删掉的小节里有句尾 → 前后两句合成一句（提示里写「第 n 小节的 2 个句尾一起删了」） |
| 复制一行 flow | 标记一起复制 |
| 清空全部 flow（`resetFlow`） | 全部标记清掉（作品回到「没断句」）；和清空一起算一步，确认条里加一句「断句也会清掉」 |
| 换伴奏 / 改 BPM | 不动（标记记在字上，字跟着拍子走） |

### 2.5 存量作品 / 旧文件

- v3 作品、v2 / v1 迁移来的作品都没有 `brk` → 没断句 → 画面和涂色规则都和 v3.2 一样。第 1 步工具条「断句」一组显示「还没断句」+「自动断句」按钮，什么都不自动做。
- 第一次加句尾时，如果某个**已经涂了色**的格子因此改押别的字（第 6 节的锚定规则），提示条写出来：「第 28 小节第 4 拍的金色现在押这一句最后 2 个字（原来押的是下一句开头）」，可以撤销。


## 3. 显示

### 3.1 一句 = 一条括线 └────┘（`phrases`）

- 参照图是「黑竖线 = 句首、红竖线 = 句尾」。照这个配色，但把两根竖线**用方格下面的一条横线连起来**，变成一个括号：一眼看出「从这里到那里是一句」。v3.2 的方格、空音、拖音画法都没动，括线画在方格**下面的空隙**里（桌面 12px、手机 10px），竖线比方格上下各长 3px。
- 句首竖线：正文色（浅色模式深灰黑、深色模式近白），3px。句尾竖线：红（`--a-error`，和「清空」按钮同一个红），3px。脚本量：两种模式下和格子底色对比都 ≥ 3。
- 横线 2px；相邻两句**一深一浅交替**（正文色 / 弱化色），快嘴段几句挤在一起时也分得开。
- 竖线放在方格之间那 4px 缝里：句首竖线贴着这一句第一个方格的左边，句尾竖线贴着最后一个字（含拖音）结束的地方。两句紧挨着时就是「红 | 深」两根并排，各 3px，**不重叠**（脚本逐行量）。
- **序号**：桌面在句首竖线右边、压在横线上写一个小号数字 = 这一段第几句（`Pre-Hook 1` 第 1–6 句）。放不下（这一句在这一行不到 18px）就不写。手机不写，点句子时在气泡里写。**不显示句号「。」**：红线已经是句号，再加一个符号像是歌词里的字。
- 跨小节的长句：横线铺到行尾，下一行从行头接着铺，中间没有竖线（`phrases` 第 20–21 小节）。
- 第 2 步（填字和韵脚）同样画括线，画在字下面（`rhyme`、`spacing`）。
- 没断句的作品：不画任何括线。只要断过一句，最后一个句尾之后的字画虚线横线（「未收尾」，`mark` 下半部分）。

### 3.2 快嘴段（`dense`）

- 第 100–105 小节是真实节奏和真实断句：第 101 小节第 1 拍、第 4 拍各有一处「上一句收尾、下一句马上开始」，红线和深线并排，横线一深一浅。
- 压力样例 S1：一小节 4 句（每句 4 个 1/16），句子之间一点空都没有，句尾都落在拍子中间。桌面每个 1/16 方格约 38px、手机约 19px，两根竖线照样分开。
- 压力样例 S2：三连第 2 个字后断句（这一拍上方照旧有「3」）；两个 1/32 之间断句（1/32 方格手机上约 10px 宽，竖线还在缝里）。

### 3.3 尺寸和配色

桌面 1280×800、手机 390×844，浅 / 深色都截了图。只用已有 token：正文色、弱化色、`--a-error`（深色 `#F87171`）、警告色（漏断提示、自动断句横幅）、强调色朱橙（选中的句尾外面一圈、光标）。没有新配色。红线和韵脚颜色（色相 10° 那种红）可能撞色——韵脚色是格子底色和字底色，红线是格子之间一根细竖线，形状不同；仍然列为拍板题 Q3。

## 4. 手动标注交互（`mark`、`touch`）

### 4.1 键盘（第 1 步改方格状态，接在 v3.2 的状态表上）

| 状态 | 输入 | 结果 |
|---|---|---|
| 改方格 | **Shift+Enter** | 光标这个字：不是句尾 → 标成句尾（`'end'`，一步）= **拆句**；是待确认的句尾 → 确认（一步）；是确认过的句尾 → 取消（一步）= **和下一句合句** |
| 改方格 | Enter / Esc | 退出改字（v3.2 不变） |
| 改空音 | Shift+Enter | 不做，提示「空音上不能断句，句尾要挂在一个字上」 |
| 输入法在拼字 | Shift+Enter | 不做，交给输入法（和 v3.2 对空格的规矩一样：`isComposing` / `keyCode 229`） |
| 空闲（没在改方格），选中了一个字 | Shift+Enter | 同上，对选中的字 |

- 为什么是 Shift+Enter：「换行 = 这一句在这里结束」，聊天软件里 Shift+Enter 也是换行；Enter 已经是「退出改字」，空格系列已经被分格占了；`/`、`.` 在中文输入法下会变成「、」「。」，keydown 不可靠。
- 不冲突：空格 = 一分二、Shift+空格 = 三连、两下空格 = 空音、退格 = 清字 / 合并、Tab / 方向键 = 换格、`-` / `=` = 拖长缩短，全部不变（脚本断言气泡里四个分格按钮原样）。唯一改动：v3.2 里 Shift+Enter 和 Enter 一样是「退出改字」（`LyricsGrid.tsx:209` 没看 Shift），v3.3 起 Shift+Enter 改成断句。
- 「从这里起新的一句」= 把前一个字标成句尾：气泡里有按钮；键盘上是 `←` 再 Shift+Enter。

### 4.2 鼠标

- **点两格之间的缝**：指针停在两个字之间（同一句里）时出现一根红色虚线和「点这里断开」，点了 = 左边那个字成为句尾（一步）。停在句尾红线上 = 可以拖，也可以点开小菜单。
- **拖红线**：左右拖，吸到字和字之间（只能吸到「有字」的地方，不吸到空音中间）；松手 = 一步「句尾从 A 挪到 B」。拖过下一句句首 = 不许（停在下一句第一个字之前）。
- 气泡（点方格出现的那个）多一行：「到这里一句」（Shift+Enter，是句尾时显示按下）/「从这里起一句」。

### 4.3 触屏（`touch`）

- 点方格 → 气泡（v3.2 那个，手机贴底部）里有「到这里一句」「从这里起一句」两个按钮。
- **点一下红线**（命中区 24px 宽，比线本身宽）→ 选中它（外面一圈强调色）+ 底部小菜单：**是句尾**（只有待确认时出现）/ **不是句尾（和下一句合并）** / **◀ 往前一个字** / **往后一个字 ▶**。每个按钮一步。按钮高 ≥ 40px（脚本断言 ≥ 36px）。
- 不做拖动（手机上拖细线容易误触滚动），只用按钮挪。

### 4.4 历史

每一次标 / 取消 / 确认 / 挪 = `editorStore.exec` 一步（单线历史，沿用 v3 规矩），`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 重做。历史条目文字例：「第 101 小节第 1 拍 → 句尾」「取消句尾：第 105 小节第 4 拍半」「句尾 第 94 小节第 2 拍 → 第 2 拍半」「自动断句：建议 60 处」「接受全部建议（60 处）」。锁定照旧：锁住的字不能改标记（整步不做，提示先解锁）。

## 5. 自动断句

两种来源**分开**，结果的可信度不一样，界面上也不一样。

### 5.1 (a) 有歌词时间戳：从歌曲提取 flow 时按歌词断句

在流水线里做（不是 AnyBeats 编辑器），写进导入文件：

1. 歌词识别给出每个词的时间。按识别的分段 + 标点 + 换行切成句子，得到每句的开始时间 `t_k`。
2. 秒 → tick：`tick = (t − offset) × BPM / 60 × 48`。
3. 第 k 句 = 起点落在 `[tick(t_k) − 12, tick(t_{k+1}) − 12)` 里的字（容差 12 tick = 一个 1/16，和主会话 `render.py` 的做法一样，样例 116 句就是这样断的）；最后一个字写 `"brk": "end"`。
4. 一句里一个字都没落进来 → 丢掉这句（识别出的词没有对应的 flow 字）。

写成**确认过**（拍板题 Q4）：它和歌词一样可信。但也会错：识别把两句连成一句、把一个词的时间放到下一拍，都会让句尾偏一个字。所以打开时提示一次「断句来自歌词识别，识别错的地方手动改」。

### 5.2 (b) 只有 flow 没有歌词：按节奏猜「建议断句」

规则（全部确定性，在编辑器里跑）：

| 规则 | 把哪里当句尾 |
|---|---|
| 空白 ≥ 半拍 | 这个字结束到下一个字开始之间空了 ≥ 24 tick |
| 段落交界 | 下一个字已经在下一段 |
| 全曲最后一个字 | 一定是句尾 |

- 全部标成**待确认**（`'guess'`，虚线）。已经确认过的句尾不动；再点一次「自动断句」只替换待确认的那些。
- 横幅（`auto` 工具条下面）：「自动断句猜了 60 处句尾（虚线 = 待确认）。只看节奏：后面空了半拍以上、或者到了下一段，就猜这里断。**快嘴段一句挨一句时猜不出来，会漏**；在这首歌上实测，按歌词断的句尾只猜中三成。」+「全部接受」「全部不要」（各一步）。
- 逐个改：点红线 → 小菜单（第 4.3 节），或者光标方格上 Shift+Enter 确认。
- **漏断提示**：连续 ≥ 4 小节（16 拍）一处建议都没有 → 在这一段前面插一条警告色提示「第 99–110 小节 12 小节没猜出一处断句。快嘴段常常一句挨一句、中间不换气，只看节奏分不出来——这里很可能漏了好几句，请手动标」，这几行行头左边一条警告色竖条。样例里有 9 段这样的地方。
- **如实说**：这条规则在样例上准确率 62%、召回 32%；快嘴段（Hook A 1、Hook A 3）几乎全漏。它只能当起点，**不能当成可靠的断句**；不确认就不参与韵脚锚定（第 6 节）、AI 也不开工（第 7 节）。
- 不做「每小节第 4 拍也猜一个」之类的补救：样例里三四成句尾不在第 4 拍，猜出来大半是错的，反而让人以为断好了（拍板题 Q5）。

## 6. 韵脚默认落句尾（和「一格一色、按格涂色」共存）

### 6.1 规则

涂色数据**不变**：`paint` 还是「格子 → 颜色」，一格一种颜色，`.anybeats` 里的 `paint` 一个字节都不变。变的只是「一格涂了色以后押哪几个字」（`rhymeWords` / `rhymeSlots`，`src/core/rhymeRules.ts:284`、`:290`）：

| 这一格里 | 押哪几个字 |
|---|---|
| 有**确认过**的句尾（这一格里某个字带 `brk: 'end'`；有好几个取最后一个） | **这一句的最后 n 个字**（n = 押数）：从句尾往前数，可以跨到前一格、前一小节，**不越过句首**；这一句不到 n 个字就押它有的那几个（和 v3「格里不到 n 个字」同一种对齐：韵母串从后往前对） |
| 没有句尾（或只有待确认的句尾，或整首没断句） | 和 v3 一样：格内最后 n 个字 |

- **一个字只押一种颜色**：句尾锚定的格子先算；它跨进前一格的字算它的。前一格要是也涂了色、又没有句尾，就在剩下的字里取最后 n 个（可能少于 n 个，界面提示「这一格只剩 1 个字可押」）。确定性，同样的表格永远同样的结果。
- 待确认的句尾不锚定：猜错的断句不能改韵脚位置。用「句尾」涂法涂一个待确认的句子 = 确认它 + 涂色，合成一步。
- 锁韵脚、「对不上」提示、AI 的 ③④ 都读 `rhymeSlots`，所以自动跟着变，不用各改一份。

### 6.2 第 2 步怎么涂（`rhyme`）

- 工具条选法多一个 **「句尾」**，有确认过的断句时默认选它：先选颜色，再**点一句里任何一个字**（或句尾红线、括线）→ 涂这一句句尾所在那一格。拖过几行 = 这几行里每一句的句尾。不用再一格一格找句尾在哪一格。
- 「单格 / 整行 / 框选 / 反选」照旧，行为和 v3.1 一模一样。要押句中韵（第 2、4 拍军鼓上的字）就切到「单格」。
- 没断句的作品：「句尾」选法置灰，提示「先在第 1 步断句」；默认是「单格」，和现在一样。
- `rhyme` 第 28 小节：句尾在第 4 拍第 2 个 1/16，后面第 4 个 1/16 是下一句的第一个字。按格子算押的是那个字（虚线框），按句尾算押的是这一句最后 2 个字「气 光」。第 22、23 小节：双押的两个字分在第 3、4 拍，只有句尾所在的第 4 拍涂了色，第 3 拍那个字照样押上（字底是同一种颜色）。

### 6.3 不会改坏现有涂法的理由

1. 没断句的作品：锚定规则不触发，`rhymeSlots` 的结果和 v3 逐字节一样（实现单加一条测试：拿 v3 的全部涂色样例跑一遍，断句为空时结果完全相同）。
2. 有断句但这一格没有句尾：结果和 v3 一样。
3. 只在「这一格里有确认过的句尾」时变，而这正是 v3 规则会押错的情况（样例 35 句）或者表达不了的情况（40 句）。
4. 涂色数据、选格子的方法、一格一色都不变。

## 7. AI 填词约束：加第 ⑤ 道程序检查「句子边界」

对照 `design/AGENT_DESIGN.md` 第 3 节的四道检查（① 锁定的格子不变、② 没开「允许改 flow」时落点不动、③ 填韵只填空格、④ 押韵按字面韵母严格比对）。原则照旧：**判定只用程序**，同样的输入永远同样的结果；不过就整份不上屏；判不出来算不过；上屏那一刻再判一次。

### 7.1 为什么是新加一道，而不是并进 ②

② 管「每个字的落点」，⑤ 管「哪些字是一句」。开了「允许改 flow」时 ② 整道不查，但句子边界仍然要守（否则开了允许改 flow，AI 就能把两句写成一句）。所以单独一道，**不受「允许改 flow」开关影响**。「句尾那几格放押韵字」不另起：它就是 ③④ 在新的韵脚位置上跑。

### 7.2 ⑤ 的判据（全部程序可判）

输入：改之前的表格 `G0`（只认确认过的句尾）、AI 的结果、选区、锁、涂色。先由程序从 `G0` 算出句子表 `P0 = phrases(G0)`。

| 编号 | 规则 | 程序怎么判 | 违规原因文字（固定句式） |
|---|---|---|---|
| ⑤a | 句尾标记 AI 不能动 | 候选稿上所有字的 `brk` 由程序从 `G0` 抄过去，不读模型输出里的任何断句字段；没开允许改 flow 时（位置集合相同）`brk` 必须逐字相同；开了允许改 flow 时，每句 `P0[k]` 的时间范围 `[startAbs, endAbs)` 里最后一个字由程序标 `brk`，**范围里一个字都不剩 → 违规** | 「第 n 句被删光了」 |
| ⑤b | 句子之间的空白不许填 | 候选稿里起点落在 `P0[k].endAbs` 到 `P0[k+1].startAbs` 之间（两句之间的空音）的新字 → 违规（不然两句的界线就糊了） | 「在第 n 句和第 n+1 句之间的空音里加了字」 |
| ⑤c | 每句的字只落在本句 | 请求按句子发：每句给出「第几句、几个字位、哪几位是韵脚、要押什么」；回答必须按句子给，`answer[k].chars.length === slots(P0[k]).length`（没开允许改 flow 时），程序按句子逐个写进本句的字位；句数、字数对不上 → 整份退回 | 「第 n 句要 12 个字，给了 13 个」 |
| ⑤d | 一个词不跨句尾 | 对每个句子交界（至少一边被 AI 改过），取前一句最后 4 个字 + 后一句前 4 个字拼起来，用**编辑器打包的固定分词器**（`pinyin-pro` 自带的分词；实现单先核对 3.29 版有没有，没有就打包一份固定词典）切词；交界处不是词边界 → 违规 | 「『循环』跨过了第 n 句句尾」 |

- 有**待确认**的句尾落在选区里：AI 不开工，面板提示「选区里还有 3 处待确认的断句，先确认再让 AI 写」（拍板题 Q7）。整首没断句：⑤ 没有可查的，照样能用，面板提示「这一段还没断句，AI 可能把一句写到下一句里」。
- 分词器的确定性：同一个版本的分词器、同一份输入永远同样的结果；分词器随编辑器打包，不跟浏览器走（`Intl.Segmenter` 的结果随浏览器内置的 ICU 版本变，不用它）。

### 7.3 ③④ 的调整（句尾放押韵字）

- ③ 填韵目标 `planRhymeFill`（`src/core/aiEdit.ts:26`）：今天是「涂了色、整格一个字都没写」的格子里的韵脚位置；改成「涂了色、**这一组韵脚位置**（句尾锚定时 = 这一句最后 n 个字，可能跨格）一个字都没写」。「已经写了字的跳过」不变（v3 拍板题 3）。
- ④ 押韵比对：判定函数不变（`rhymeSlots(候选稿, rules, paint, 'strict')`），位置自动变成句尾锚定的位置。所以「句尾那几格放押韵字」= ④ 在句尾位置上判 `ok === true`，没有新的比对逻辑。
- ①b「锁韵脚时韵脚位置不许换人」：同样读 `rhymeSlots`，自动按句尾锚定。② 不变。

### 7.4 和 AGENT_DESIGN 的对齐

| AGENT_DESIGN 已定 | v3.3 | 去向 |
|---|---|---|
| 四道检查（§3.1 总表） | 五道：加 ⑤ 句子边界 | 实现单在 `core/aiGate.ts` 里加 `judgePhrases`，`judgeAiFill` / `judgeAiPolish` 都调；不改 AGENT_DESIGN 本文（受保护），在实现单报告里写明 |
| 只在前端执行（§3.3） | ⑤ 也只在前端；分词器打包进编辑器 | 一致 |
| 不过就整份退回，重写上限 2 次（§3.4） | ⑤ 不过同样整份退回；违规句式加进 `CHANGE_REASON_TEXT` | 一致；`ChangeReason` 再加 `phrase-cut`（跨句）、`phrase-gap`（填了句间空音）、`phrase-count`（字数不对）、`phrase-pending`（有待确认） |
| ③「整格一个字都没写」 | 「整组韵脚位置一个字都没写」 | 第 7.3 节 |
| 提示词 | 加句子结构（每句几个字位、哪几位押什么） | 只是帮模型写对，**判定不看提示词** |

## 9. 拍板题

**Q1 句尾存在哪？**
- A（推荐）挂在字上（`Word.brk`）。B 独立的句子表 `{start, end}`。C 断点 tick 表。
- 依据：A 跟着字走，插删小节、分格合格、复制、撤销都不用额外维护；B / C 的端点会落到空白上，要一整套修复规则（第 2.1 节）。

**Q2 `.anybeats` 要不要升版本号？**
- A（推荐）不升，还是 3，字上加可选字段 `brk`。B 升到 4，旧版 AnyBeats 打开新文件直接报「更新的版本存的」。
- 依据：线上只有一个版本；不升的话旧文件、新文件、流水线写的文件都能被同一个读取函数读；代价是旧版读新文件会悄悄丢断句（残留风险）。

**Q3 句尾用什么颜色？**
- A（推荐）红（`--a-error`），句首正文色，形状是括号的两端。B 都用正文色，只靠括号形状区分。C 句尾用强调色朱橙。
- 依据：A 和你看过的参照图一致、一眼分得开；C 会和光标、选中框（都是朱橙）混；B 最安全但快嘴段一眼看不出哪根是尾。韵脚颜色里有一种接近红（色相 10°），但它是底色，红线是细竖线，形状不同。

**Q4 按歌词断的句尾，导入后算确认过还是待确认？**
- A（推荐）确认过，打开时提示一次「来自歌词识别，错的手动改」。B 也标待确认，要你一处处点。
- 依据：116 句一处处点很累；歌词断句的错是个别的，按节奏猜的错是成片的，两者不该同样对待。

**Q5 只有 flow 时，快嘴段漏断怎么办？**
- A（推荐）只提示「第 99–110 小节可能漏了好几句，请手动标」，不硬猜。B 在长段里每小节最后一个字也猜一个（低把握）。C 不提示。
- 依据：样例里三四成句尾不在第 4 拍；B 猜出来的大半是错的，还会让你以为已经断好了。C 不诚实。

**Q6 句子序号要不要显示？**
- A（推荐）桌面显示（句首旁小数字，放不下不写），手机不显示、点句子时在气泡里写。B 都不显示。C 都显示（手机字号会小于 10px）。
- 依据：序号方便你和 AI 说「第 3 句」；手机格子太窄，硬塞会和竖线挤在一起。

**Q7 有待确认的断句时，AI 能不能写？**
- A（推荐）不能，先确认（只看选区里的）。B 当成没有断句照样写。
- 依据：你担心的就是 AI 把句子位置搞混；待确认的句尾 4 成是错的，拿它约束 AI 等于用错的规矩去管它。

**Q8 韵脚间隔视图做不做？**
- A（推荐）做，默认开，只写拍数和「早 / 晚」提醒。B 做，默认关。C 不做。
- 依据：主会话的结论就是「句尾决定位置、节拍检查间隔」，间隔是第二件事的直接显示；只写字不画线，不占表格。

**Q9 第 2 步「句尾」涂法要不要设成默认？**
- A（推荐）有确认过的断句时默认「句尾」，没有时默认「单格」。B 永远默认「单格」，「句尾」要自己切。
- 依据：你说的是「涂韵脚时默认落在句尾」；没断句的作品默认单格，和现在完全一样。

**Q10 涂了色的格子里正好有句尾、但你想押的是句尾后面那个字（下一句开头当句中韵）怎么办？**
- A（推荐）这一期不做逃生口：先取消那个句尾或把颜色涂到下一格。B 每格加一个「按格内最后一个字押」开关。
- 依据：样例里没有这种用法；加开关会让「这一格押哪个字」又多一个分支。真遇到了再加。

## 12. 自动检查和反向探针

`python -I design/check_mockups_v33.py design [证据目录]`：7 个画面 × 2 尺寸 × 2 配色 = 28 个组合，每个都在 Chromium 里打开、截图、量算，**不 grep 源码**。

- 通用：无控制台错误、无外网请求、不左右溢出、当前步骤对；气泡 / 小菜单 / 横幅 / 提示条在视口里，而且四个角都没被工具条、抽屉、别的浮层盖住。
- 句首 / 句尾竖线：看得见（宽 ≥ 2.5px、不比方格矮、和格子底色对比 ≥ 3）、不越格、落点对（±1.5px，按 tick 算）、句尾是红色 / 句首是中性色（浅深色都量）、待确认的是虚线 / 确认过的是实线。

- **断句位置和样例数据对得上**：看得见的每根句尾都在 `koi_phrases.json` 里，样例里结束点落在看得见格子里的句尾一根不少（按歌词 / 自动断句分别对）。
